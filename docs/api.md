# Server API

Every route under `server/api/` and `server/routes/`, and what the server does beyond its schema: caching, behaviour and the reasons for them. [openapi.json](openapi.json) is the reference for the routes, their inputs, status codes and sessions. It is generated by `npm run openapi` from the route manifest in `server/openapi/` and the zod schemas in `server/schemas/`, and `npm run lint` fails when it drifts. This document does not repeat what the document states. The body of each response is a named schema in its `components.schemas`; it is written in `app/schemas/` and tied to the interface of `app/interfaces/` that the app reads, so a change to either fails `npm run typecheck`. Who may call each route and how it is protected is in [security.md](security.md).

Conventions:

- **Errors** under `/api/` are answered as problem details ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457), `application/problem+json`, [ADR-0015](adr/0015-problem-details.md)): `type` (always `about:blank`), `title`, `status`, `detail` (a fixed English text for developers, never upstream text) and `code`, a stable camelCase identifier that a client branches on. For one release line the Nitro members `statusCode`, `statusMessage`, `message` and `data` (with `data.code` on every error; `statusMessage` is the code on auth routes and the status text or a fixed route text elsewhere) stay as extension members; the client translates by `code` (see [Error codes](#error-codes)). An error nobody handled is a 500 with code `internalError`.
- **Locales** are `en` and `es`. An unknown locale is a `400`; an empty one counts as absent.
- **502** means Strapi failed or rejected the call. The message is a fixed one that the route chooses (`Failed to fetch comments`): Strapi's own text and the URL of the call are never returned, they go to the log. A 404 from Strapi stays a 404, a posted comment that Strapi refuses stays a 400, and any other status (a 401 or 403 included) is a 502.
- **429** comes with `Retry-After` (seconds).
- **413** answers a request body over 64 KB, declared or counted as it arrives; the rest of the body is not read and the connection is closed. Every route that reads a body applies it.

**Site identity.** `/api/site` reads Strapi's `site-setting` single type (3 s timeout) with nested `populate: { author: true, logo: true, favicon: true, defaultOgImage: true, socialLinks: true, modules: true, theme: { populate: '*' }, homePage: { fields: ['slug'] } }` and merges it over the `site` block of `app/app.config.ts` field by field (`app/helpers/site.ts`). The query is built with `qs.stringify` because ofetch's `query` option does not serialize nested objects. Each Strapi field is validated on its own (`server/schemas/site.ts`): an invalid or empty value, or one that is missing, keeps the `app.config.ts` value, and so does every field when Strapi fails or times out. The `app.config.ts` defaults are neutral (name `Micelio`, everything else empty) and an empty value renders as absent: no link, no contact line, no date, no JSON-LD field. A module left unset in Strapi stays on. Pages read it through `useSite()`, which returns the `app.config.ts` values until the route answers. Server code reads it with `loadSite(locale)` (`server/utils/site.ts`): the RSS feeds take the site name for their titles and `<generator>`, and the newsletter emails for their subject and body. `logo`, `favicon` and `defaultOgImage` come back as absolute URLs when `NUXT_PUBLIC_STRAPI_URL` is set (otherwise they are unchanged): a relative one (Strapi's local upload provider, e.g. `/uploads/logo.svg`) is resolved against `NUXT_PUBLIC_STRAPI_URL` in `loadSite()` (`resolveSiteMedia`), URLs with a scheme (R2, CDN, `data:`) stay as they are and `//host/x` becomes `https://host/x`; the favicon from `app.config.ts` or the theme is a path on the site and is not touched. The Strapi origin is already allowed in the CSP `img-src`. There is no allow-list: `loadSite` builds the answer field by field (`siteFromAppConfig`, `mergeSite`, `resolveTheme`) from values `parseSiteSettings` already validated, so the response schema is strict.

**Home page.** `site-setting.homePage` (a relation to `page`, localized: each language names its own page, `showcase` and `muestra`) is exposed as `Site.homePage?: { slug }`; it is absent when none is set, and a slug that is not a Strapi uid is dropped alone. `app/pages/index.vue` reads it (`useLoadedSite()`) and, when set, renders that page at `/` and `/es` with `/api/pages/<slug>` and the same body and SEO as `app/pages/[slug].vue` (`SectionRenderer` with `page-title`, `usePageSeo`; canonical is `/` or `/es`). Without `homePage`, or when the page does not load (404 or any error), `/` renders the blog home exactly as before (`useBlogHome()`, `RegionHome`) and the server logs a warning (`warnOnce`, `app/helpers/pages.ts`: once per locale, slug and status every ten minutes, at most 100 keys); it never answers 404. The page also keeps answering at its own `/<slug>` with a canonical to `/`, no redirect. hreflang always points at canonical URLs (`useAlternates`, `homePaths`/`pagePaths`): each translation is listed at its language's root when it is that language's `homePage` (read from `/api/site?locale=` of that language, on the server only, hydrated from the payload), otherwise at its own slug, so `/` and `/es` point at each other only when both are home pages. Freshness: `/` and `/es` keep their ISR rule (300 s), so a change to the home page or to `homePage` shows after up to the site cache (60 s, `siteCacheSeconds`) or the page cache (300 s, `loadPage`) plus the ISR window (300 s).

**Theme overrides.** When Strapi's `site-setting.theme` has `themeId`, `defaultMode`, `accentOverrides` or `displayFont` (ADR 0005, section 8), the server resolves them against the active build theme (`NUXT_PUBLIC_THEME`); a foreign `themeId` is ignored and logged once. Resolution rules: `defaultMode` is kept only if it is a mode of the theme; `displayFont` (one of five curated fonts, ADR 0005 section 8) is looked up in a table keyed by the enum and rendered into the page head: its `@font-face`, its `<family> Fallback` faces and `--font-display`, plus a `<link rel="preload" as="font">`; the font the theme already uses for display (Bogotá: Archivo, starter: Fraunces) emits nothing, and the mono family is never overridden; `accentOverrides` are checked per mode, an override for an unknown mode is dropped, and an accent equal to the theme's is dropped. For each accent, the server checks contrast against ADR 0005 §1 rules and WCAG 2 AA levels on the theme's three surfaces in that mode (and `link`, `focus` and `link-soft` when the theme defines them from the accent); if it fails, the nearest OKLCH lightness that passes is used, keeping hue, and the adjustment is logged; when none passes, the theme's accent is kept. The server derives `accent-soft` (14 % OKLab into `surface`), `accent-hover` (80 % with `ink`) and `on-accent` (the theme's `ink` or `on-ink`, whichever contrasts more). The result appears in the `theme` field of the response when anything changes; this field is absent otherwise. When `defaultMode` applies, the server writes that mode into `data-theme`, `data-scheme` and `data-mode-default` on `<html>` (the init script still prefers the visitor's stored choice). The accents are rendered into one `<style id="theme-overrides">` in the SSR head (see security.md), cached with the page under ISR (ADR 0001) and refreshed with `loadSiteCached()` (cache: `siteCacheSeconds`, 60 s default, or at most 10 s when Strapi failed). `theme.id` is the active build theme, `theme.defaultMode` the resolved mode or absent, `theme.displayFont` the chosen font or absent, `theme.accents` a map of mode id to `{ accent, accentSoft, accentHover, onAccent }`, all as `#rrggbb`.

**Pages.** `/api/pages/:slug` asks Strapi for one `page` (`/api/pages` with `filters[slug][$eq]`, `locale` and `pagination[limit]=1`, built with `qs.stringify` into the path) and populates `seo` (with its image), `localizations` (`slug`, `locale`) and the `sections` dynamic zone with one `on` entry per component naming each nested link, media and relation (`PAGE_POPULATE`, `server/utils/pageSections.ts`). The answer is a `Page`: `documentId`, `title`, `slug`, `locale`, `seo` (`PageSeo`), `sections` and `translations` (`{ locale, slug }[]`, for hreflang). Validation is lenient (`server/schemas/page.ts`): a section with an unknown `__component` or that fails its schema (a missing required field, an unknown `variant`, a scene model that is not a `.glb` (a `.gltf` names external buffers the island would not fetch)) is dropped alone and the page stays; an optional field that is invalid (a bad link or media URL) is dropped alone; list items are dropped one by one, and a section left with none is dropped; a missing `variant` takes the CMS default. Links are `http(s)`, `mailto:` or a path starting with a single `/` and no backslash (`//host` and `/\host` leave the site, so they are dropped); logo links are `http(s)` only; media is `{ url, alternativeText?, width?, height?, mime? }` and its URL is a path on the site or on an origin the CSP already allows for images (`NUXT_PUBLIC_STRAPI_URL`, `NUXT_MEDIA_URL`), anything else is dropped. In `seo`, `canonicalURL` is kept only on the origin of `NUXT_PUBLIC_SITE_URL` and `metaRobots` only when every comma-separated token is a documented robots directive (`noindex`, `nofollow`, `max-image-preview:large`…); `metaSocial` and `structuredData` are not returned. A page with no valid title or slug answers 404. Markdown is rendered and sanitized on the server (as above): `media-showcase.text` becomes `html`, each FAQ `answer` becomes `html`, `rich-text.body` becomes `html`, and the sources are not returned. Plan `features` come as a `string[]`, one per line. Each `post-list` section (the first four of a page; later ones come with `posts: []`, so a page costs at most four extra Strapi calls) carries its `posts` (`PostListItem[]`, newest first, at most `count`, 1 to 12), looked up by the category or tag slug (the category wins if both come) with the same populate as `/api/posts`, and each card goes through the allow-list of `server/lib/publicShapes.ts` (`publicPostCard`), so it carries only the keys of `PostListItem`; no match or a Strapi failure gives `[]` and the page still answers. Cache: the fetch, validation, Markdown rendering and post lists run inside a Nitro `defineCachedFunction` (`loadPage`, name `page`, key `<locale or default>:<slug>`, 300 s, stale while revalidating), so repeated hits cost no Strapi call. A page that is not found (`undefined`) and every error are not stored, so a page published a moment later appears at once. `Cache-Control: public, s-maxage=300, stale-while-revalidate=600` is only defensive on success, as in the other routes (ADR 0001); Nitro answers errors with `no-cache`.

**Page route and reserved slugs.** `app/pages/[slug].vue` renders a page at `/<slug>` and `/es/<slug>` (the slug differs per locale: `/showcase` and `/es/muestra`), calling `/api/pages/:slug?locale=`. A 404 or a 400 (a slug that is not a valid uid, like `/Showcase`; `/About` is the about page, the router ignores case) answers the normal 404 page; a slug that is not a uid is rejected by the route before any call; any other error keeps its status, and a failure without one (network) is a 500. Static routes win over the catch-all, so these slugs never reach a page and a CMS page with one of them is unreachable: `about`, `blog`, `privacy`, `confirm`, `account`, `drafts`, `newsletter` and `_theme` (plus `api` and the files served by `server/routes`: `feed.xml`, `sitemap.xml`, `robots.txt`). SEO comes from `seo` (title falls back to the page title, `metaRobots` becomes the robots meta, `canonicalURL` replaces the page URL as canonical); hreflang comes from `translations`, so the locale switcher goes to the translated slug. `metaSocial` and `structuredData` are not rendered. The page is server-rendered on each request (no ISR rule, ADR 0001); the API behind it is cached. The h1 is the title of the first section when it is a hero; otherwise it is the page title.

**Fields returned.** `/api/posts`, `/api/posts/:slug`, `/api/drafts/:documentId` and `/api/about` rebuild the CMS answer from an allow-list (`server/lib/publicShapes.ts`), and so do the cards of the `post-list` sections of `/api/pages/:slug`: a card carries `RawStrapiArticle`'s `id`, `documentId`, `title`, `slug`, `locale`, `description`, `publishedAt`, `readTime`, `tags`, `cover`, `category`, `author`, `seo` and `snippet`; a full article adds `updatedAt` (the draft strip reads it), `coverCredit`, `blocks`, `references` and `localizations`. Files carry `url`, `alternativeText`, `caption`, `width`, `height` and their ids; `seo` leaves out `metaSocial` and `metaViewport`; a block with an unknown `__component` is dropped. `createdAt` and every other field the CMS stores are not returned; so is `content`, the legacy Markdown body that `blocks` replaced (the CMS article schema has no such field). A new CMS field reaches the browser only when the allow-list names it. A change to an allow-list must update the response schema in `app/schemas/`; `test/responseAllowList.test.ts` fails when a key is in one and not the other. The Strapi queries follow the same lists: the article and About populates (`ARTICLE_POPULATE`, `ABOUT_POPULATE` in `server/lib/constants.ts`) name each nested component and the image fields instead of `populate: '*'`.

**Rendered Markdown.** `/api/posts/:slug`, `/api/about` and `/api/drafts/:documentId` render Markdown on the server (`app/helpers/markdown.ts`, labels from `i18n/locales/` in the request's `locale`): every `shared.rich-text` and `shared.quote` block gets an `html` field, and every `about.open-source` guide item an `html` field, already sanitized. Article citations are numbered on the server from the article's `references`. `body` and `text` are still returned for the table of contents and the reference list. Components render `html` and never parse Markdown in the browser.

**Playground blocks.** The article query (`ARTICLE_POPULATE` in `server/lib/constants.ts`, used by `/api/posts/:slug` and `/api/drafts/:documentId`) also populates `shared.playground` (`'shared.playground': true`; Strapi 5 drops components a fragment populate does not name). The block arrives as `StrapiPlayground` (`app/interfaces/strapi-blocks.ts`): `runtime` (`python`, `sql` or `javascript`), `code`, and optional `expectedOutput`, `setup` (hidden code that runs before `code`; the page never shows it) and `caption`. Nothing is rendered or transformed on the server: `StrapiPlaygroundBlock` shows the code (`MycCodeBlock`), the expected output and the caption as escaped text, so the block works without JavaScript. An unknown `runtime` renders as a plain code block with its output. `/api/about` does not populate it.

## Modules

Each site turns features on and off in Strapi's `site-setting.modules` (all on by default). The server switches a module off by itself when it lacks what it needs, and logs it at startup: `newsletter` without the four SMTP settings, `fediverse` without the three `NUXT_PUBLIC_FEDIVERSE_*` values, and `drafts` whenever `accounts` is off. `/api/site` returns the result (`modules`), and pages read it with `useModule(module)`. The site mode (`NUXT_PUBLIC_SITE_MODE`: `dynamic` by default, `static` or `landing`; ADR 0006) also limits them. It is read at build time, exposed as `runtimeConfig.public.siteMode`, and the server fails at startup if a runtime value differs from the build's. In `static` and `landing`, `comments`, `accounts`, `drafts` and `fediverse` are always off, `newsletter` is on only when `NUXT_PUBLIC_NEWSLETTER_FORM_ACTION` is set (SMTP is not used; in a static build the action is baked into the prerendered pages, so it must be set at build time; `NUXT_PUBLIC_NEWSLETTER_FORM_FIELD`, default `email`, names the provider's email field), and `search` and `support` follow Strapi. SMTP and fediverse settings are not required in those modes. All of it lives in `app/helpers/modules.ts` and `app/helpers/siteMode.ts`.

| Module | Routes and pages that answer 404 when it is off |
| --- | --- |
| `newsletter` | `/api/newsletter/*`, `/confirm`, `/newsletter/*` |
| `comments` | `/api/comments*` |
| `accounts` | `/api/auth/*`, `/account*` |
| `drafts` | `/api/drafts*`, `/drafts*` |
| `fediverse` | `/api/fediverse/*` |
| `search` | `/api/search` |
| `support` | none (only the support button) |

A switched-off module answers `notFound`, the same as a route that does not exist. Pages match with or without the `/es` prefix. `server/middleware/modules.ts` answers before the route runs, so a switched-off module never reaches Strapi. It reads the modules through `loadSiteCached()`, which keeps the site for `NUXT_SITE_CACHE_SECONDS` (60 by default, at most 10 s after a Strapi failure; `0` turns the cache off). Client-side navigation is checked by `app/middleware/modules.global.ts`.

## Comments

`relation` is required on every comment route and must be `api::article.article:<documentId or slug>`, or the answer is `400`.

| Route | Cache | Notes |
| --- | --- | --- |
| `GET /api/comments` | — | A 429 is the CMS's own limit. |
| `GET /api/comments/flat` | — | A 429 is the CMS's own limit. |
| `POST /api/comments` | — | A 429 comes at 10 per IP per 10 minutes, or from the CMS's limit, with its `Retry-After`. `author.avatar` is optional and must be `http(s)`; an invalid one is dropped, not refused. When Strapi refuses the comment, the answer is a 400 `invalidRequest` or a 404 `notFound`. |

Every comment response hides `PENDING` and `REJECTED` comments and never includes the author's email. The author id of a posted comment is set by the server (`guest-<uuid>`). The tree answers a bare array; the flat list answers `data` with `pagination` beside it (the comments plugin does not use `meta`). Every comment is rebuilt by `toPublicComment` from a list of public fields; the envelope of the flat list is the CMS answer spread, with no allow-list.

## Newsletter

| Route | Notes |
| --- | --- |
| `POST /api/newsletter/subscribe` | The 400 message is `Email is required` or `Invalid email format`. `locale` is `es` for Spanish and English for anything else. A 429 comes at 10 per IP and 3 per email per hour, or from the CMS's limit. A 500 also comes when the confirmation email cannot be sent; the pending record is then deleted, so nothing is left stored. |
| `POST /api/newsletter/confirm` | A missing token is a 400 `invalidToken`; an unknown or malformed one is a 404 `notFound`. A 429 is the CMS's own limit. |
| `POST /api/newsletter/unsubscribe` | A malformed token is a 400 `invalidToken`. A 429 is the CMS's own limit. |

Every newsletter response is `private, no-store`. The CMS stores the SHA-256 of the confirmation and unsubscribe tokens, not the tokens the emails carry, and the server looks a subscriber up by that hash, so a token never reaches the CMS's access logs (ASVS V14.2.1). Subscribers stored before this still have their tokens in the clear and keep working: if no hash matches, the server tries the token as it is, and a confirmation re-stores the unsubscribe token hashed. The unsubscribe token is created when the subscriber confirms, not when they subscribe.

All account routes answer `private, no-store`. The session is the `__Host-micelio_session` cookie set by sign-in. For one release line a request that carries only an old cookie (`micelio_session` or `bd_session`) is still authenticated: `server/middleware/session-rename.ts` re-issues the session as `__Host-micelio_session` (same attributes) and clears the old cookie on `/api/auth/**` and `/api/drafts/**` (TODO(#422): remove).

| `POST /api/auth/confirm-email` | `confirmation` is the 40-hexadecimal-character token of the email link. Confirms the address and sets no session; an unknown or used token answers `invalidCode`. |
| `POST /api/auth/resend-confirmation` | — |
| `POST /api/auth/forgot-password` | — |
| `POST /api/auth/reset-password` | — |
| `POST /api/auth/logout` | — |
| `POST /api/auth/change-password` | `password` is at least 10 characters and differs from the current one. The CMS checks `currentPassword`. |

## Error codes

Every `code` an `/api/*` error can carry, from `PROBLEM_CODES` in `server/utils/problem.ts`. `test/problemDocs.test.ts` fails when this table and the catalog differ. A route answers a code with the status listed here, and [openapi.json](openapi.json) names the codes each route can answer. The first twelve are the codes of the auth routes (`invalidInput` is also the code of a refused body on comments and the newsletter); the account forms translate each of those into the visitor's language, and other clients show their own text.

| Code | Status | Meaning |
| --- | --- | --- |
| `invalidInput` | 400 | The body does not match the schema of the route |
| `invalidCredentials` | 400 | Wrong identifier or password |
| `emailNotConfirmed` | 400 | The account exists but its email is not confirmed |
| `invalidCode` | 400 | Expired or unknown reset code, or an email confirmation token that is unknown or already used |
| `wrongPassword` | 400 | Password check failed when changing a password or deleting the account |
| `weakPassword` | 400 | The password does not meet the strength rules |
| `commonPassword` | 400 | The password is too common |
| `unauthorized` | 401 | No valid session |
| `forbiddenOrigin` | 403 | Missing `Origin` header or from another site |
| `emailTaken` | 409 | Username or email already registered |
| `tooManyRequests` | 429 | A rate limit, ours or the CMS's; `Retry-After` says when to retry |
| `unknown` | 502 | Any other CMS failure on an auth route |
| `invalidRequest` | 400 | A parameter of the query, the path or a CMS read is malformed or invalid |
| `invalidToken` | 400 | A newsletter token is missing (`confirm`) or missing or malformed (`unsubscribe`); `confirm` answers an unknown or malformed token with `notFound` |
| `notFound` | 404 | The resource does not exist, or its module is turned off (a closed module looks like absence) |
| `methodNotAllowed` | 405 | The route does not accept the HTTP method; `Allow` lists the ones the site serves |
| `payloadTooLarge` | 413 | The request body is larger than the route accepts |
| `upstreamUnavailable` | 502 | The CMS (or the analytics server) failed or is unreachable; never carries its text |
| `internalError` | 500 | The server failed, or an error nobody handled |
| `requestRejected` | 400 | Any other refusal that has no code of its own |

## Static build (`npm run generate`)

With `NUXT_PUBLIC_SITE_MODE=static` (or `landing`; ADR 0006), `npm run generate` writes a site with no server to `.output/public`. It needs `NUXT_PUBLIC_STRAPI_URL`, `NUXT_STRAPI_API_TOKEN` (a read-only token, `docs/security.md`), `NUXT_PUBLIC_SITE_URL` and, for Strapi images, `NUXT_MEDIA_URL`; the build fails with a message if Strapi is unreachable or the token is missing. `modules/static-routes.ts` reads every published article and page per locale from Strapi (`/api/articles` and `/api/pages`, `fields[0]=slug`, 100 per page, through `strapiRequest`) and adds their routes, the feeds (`/feed.xml`, `/feed/<category>.xml` and the `/es/` ones), `sitemap.xml` and `robots.txt`; the crawler adds the rest of the links. A route Strapi lists that does not render fails the build; a dead link found by the crawler is only logged. Pages carry the `noScripts` route rule, have no ISR and no payload, and the build fails if any generated page still references `/_nuxt/*.js`, `__NUXT__` or `_payload.json`. The account, drafts, newsletter, `/_theme` and the comments, auth, drafts, fediverse and newsletter APIs are not generated; images from `NUXT_PUBLIC_STRAPI_URL` and `NUXT_MEDIA_URL` are optimised into `_ipx/` during the build. The build also writes `.output/public/_headers` (one `/*` rule with the CSP and the security headers, and `Cache-Control: public, max-age=31536000, immutable` for `/_nuxt/*` and `/_media/*`, `public, max-age=0, must-revalidate` for `/_ipx/*`, and a tighter second CSP for `/_media/*`; Cloudflare Pages and Netlify format) from the hashes of the inline scripts of every page, and fails naming the pages if they differ. Each page carries the same CSP, minus `frame-ancestors`, as a `<meta http-equiv>` for hosts without `_headers`. `200.html` is not generated, so hosts serve `404.html` (status 404) for unknown paths; make sure the host is not set to a single-page-app fallback. Files copied to `_media/` are named after a hash of their bytes. `@nuxt/image`'s inline `onerror` is removed from the HTML (the CSP would block it). With `landing` and no published article in any locale, `runtimeConfig.public.blogEnabled` is `false` (set by `modules/static-routes.ts` at build, never by an environment variable): `/blog`, its filters and the feeds are neither generated nor crawled, `GET /feed*.xml` answers 404, and `sitemap.xml` lists only `/`, `/es`, `/privacy` and `/es/privacy` (docs/operate/static-site.md, "Landing"). `npm run test:landing` generates a landing against the mock Strapi and runs `e2e/landing/`. `npm run test:static` generates against the mock Strapi and runs `e2e/static/`; `node scripts/static-serve.mjs` serves `.output/public` locally, applying `_headers` (`/*`, `/prefix/*` and exact paths) and answering 404 with `404.html`.
